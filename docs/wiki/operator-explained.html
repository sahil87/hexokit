The operator watches your agents, so you don't have to.

When you run several AI coding agents at once, someone has to keep an eye on them. The operator is the AI that does that job. It notices when an agent finishes, gets stuck or asks a question, handles what it safely can, and calls you for the rest.

What it does

Notices

An agent stopped, a PR's checks finished, a pane closed.

Nudges

Tells an idle agent to carry on, or restarts one that got stuck.

Answers

Routine prompts such as "Proceed with apply?" that its rules cover.

Tells you

A notification when something needs a human decision.

It never does these on its own: merge a PR, close one, delete a branch or worktree. Those always come to you.

How it works

The operator is a loop that runs every few minutes, and sooner when an agent stops. Most of the time nothing has changed, so most passes end before any AI is involved.

  • Checking is free

    A plain program decides whether anything changed. The AI only wakes up when there is something to think about.

  • Every run starts fresh

    No run carries the history of the last one, so the hundredth run is as quick, cheap and well-briefed as the first.

  • Notes are the memory

    Anything that should last is written down on the item it concerns: "hold this PR for me", "nudged once at 14:05".

Why it's built this way

The first operator was a single chat session that never ended. Every few minutes the clock typed "check again" into it. That works, but a chat reads its whole conversation every time it replies, so each check got slower and more expensive as the day went on. When the conversation got too long, it was summarised, and the summary left out the operator's own rules.

Words you'll see

Operator
The AI that watches your other agents and your PRs.
Tracked item
Something the operator watches: an agent's tab, a PR, a reminder.
Check
A quick look by a plain program to see whether anything changed. Free.
Run
A short, fresh AI session started only when a check finds a change.
Note
A line saved on a tracked item. Notes are how the operator remembers.
Chat
Where you talk to the operator. In HexoKit, press ⌘J. Any agent tab can also become an operator chat by typing /fab-operator.

For builders: where each part lives

The whole operator moves into HexoKit, autopilot included. fab only offers plain commands and files it already has. Calls go one way, from HexoKit to fab, and fab stays optional: without it, the operator still watches panes, PRs and shell probes.

HexoKit owns

  • Tracked items and their notes, as plain files under HexoKit's state folder.
  • The clock and the check. The daemon already has the clock and wake-on-agent-stop, so the check is a function it calls directly.
  • Starting each run in its own tmux window, so restarting the daemon can't kill a run halfway (run-kit Principle II).
  • The run brief, the chat skill, and the ⌘J drawer.
  • Autopilot: the queue, its three merge modes (cherry-pick-ladder, merge-auto, stacked-prs) and ordered merging, as tested Go code instead of skill text.

fab provides (all exist today)

  • .status.yaml, which HexoKit already reads, to tell when a change is done.
  • fab status set-base-branch, so a stacked change's PR targets the right branch.
  • /fab-new and /fab-proceed, used as the opening prompt when HexoKit starts an agent on a fab change.
  • fab agent operator --headless, which tells HexoKit how to launch a run for your chosen AI provider.

Order of work

  1. Move the engine. Port tracked items and the change check into rk: about 4,400 lines of Go and 5,200 lines of tests. rk can import fab's existing state file, whose path it already knows.
  2. Build the new loop in HexoKit: check, fresh run, note. A short run brief and a chat skill replace about 160KB of skill and command docs. Autopilot rides along in the brief as text for now.
  3. Hand over and cut over. fab's fab operator commands become deprecated wrappers for one release, then each tmux server switches to the new loop, with you present.
  4. Port autopilot to Go and take its text out of the brief. Then delete fab's operator code.
