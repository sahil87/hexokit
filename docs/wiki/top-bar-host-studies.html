Top Bar Host Studies: one bar, host as the root crumb

Design study (261124 discussion). The goals are to use the space at the top of the window better, make switching hosts easier, and stop relying on the host accent colour as the only way to tell hosts apart. §1 is how the shell window looks today. §2 compares ways to show which host you're on. §3 and §4 are the two layout options as live mocks: A merges the titlebar strip into the top bar, B turns the strip into a row of host tabs. §5 is option C from the review: a row of colour squares with a host nameplate. §6 covers the crowded macOS left edge, §7 covers browser and phone, §8 compares the costs, and §9 has the recommendation. All host data is made up.

1Today: two bars, with colour as the host identity

This is the desktop shell window as it looks today. The native titlebar is hidden, and the SPA draws a 28px strip above its top bar. Hover a numbered note to highlight the part it describes. Click ws-01 ▾ to open today's host menu.

  1. The strip is a full-width, 28px band with one control in it. Apart from the traffic lights and the label, it's a drag surface painted with a 35% blend of the host colour. Every view pays that height. Turn on drag regions to see how much of it is empty.
  2. The only place the host name appears is centred in the strip, a whole bar away from the breadcrumb that names everything below the host.
  3. The HexoKit wordmark sits where the root of the hierarchy should go (Host › Workspace › Group › Tab). After the first launch it tells you nothing.
  4. The same word four times: the workspace, group and tab are all called hexokit, and the wordmark makes four.
  5. The 2px stripe and 6.5% wash repeat the host colour on the bar itself. Colour is the only signal of which host you're on.
  6. Background hosts that need you stay hidden until you open the menu. Today that's mac-mini with 2 waiting and laptop with 1.

2How to show which host you're on: colour, name, kind, monogram

The instance accent comes from a palette of about ten families, blends included, so hosts end up with neighbouring hues. With 3 hosts you learn the colours. With 6 or 7, purple, violet and indigo stop being different hosts. Use the vision filter to see the table as people with red–green colour blindness see it, or in greyscale (roughly what peripheral vision gets). The text columns still work. The colour column doesn't.

The kind glyph needs no setup: it's worked out from the host's origin (Constitution VII). A loopback address on a port in 3100–3199 is an rk remote SSH tunnel. Any other loopback address is this machine. Anything else is a network host (Tailscale or LAN). Monograms are initials, and a numeric suffix keeps its number (ws-01 → W1). They only show up as a fallback when the bar runs short of space.

Lead with the name, and add the kind glyph as a second, automatic signal. Colour either goes or shrinks to an optional 7px dot on the glyph. Keep the accent for the dock icon and favicon, which are the only cues visible in Cmd-Tab and the browser's tab strip.

3Option A: one bar, with the host as the root crumb

The strip goes away and the top bar becomes the window's titlebar. The traffic lights (or the Windows ─ ▢ ✕ overlay) sit on the bar, and the gaps between controls are the drag surface. One CSS rule exempts every interactive element from dragging, so no per-control bookkeeping is needed. Turn on drag regions to see it. The host becomes the first breadcrumb, using the same ▾ switcher style as every other level. Background hosts appear as chips when there's room and fold down to a ●N badge when there isn't. Drag the width slider to watch the fold. Click a chip or a menu row to switch hosts.

The fold order is approximate. It extends the bar's existing measured overflow. On the left: host chips → monograms → badge, then the workspace crumb, the history arrows, + Tab → +, and finally the host crumb shrinks to its monogram, then to its glyph. The host crumb is never removed. On the right, controls move into the ▾ overflow in their usual order. Refresh is already in the overflow menu in A. It reloads the whole page and is the bar's least-used button.

Finding: because the heading is truly centred, the left half of the bar gets only (bar − heading) / 2. With a 260px sidebar, chips with full names need a window about 1650px wide. Around 1300–1600px they show as monograms (MM ●2), and below that they become the badge. On most laptops, then, A works as "monogram chips or a badge", which is why the badge is the real default and the chips are a bonus.

4Option B: keep the strip, turn it into host tabs

The titlebar row stays, but now it shows every host as a browser-style tab, with its kind glyph and waiting count. The active tab joins the bar below it. Switching is always one click, and you can always see which background host needs you. The trade-off: the row stays, at 34px it's 6px taller than today's strip, and tabs shrink to monograms or scroll once you have a lot of hosts.

There's no × on host tabs. Closing a tab would mean removing a host, which shouldn't be one stray click away. Remove stays in the host menu with its confirmation. In a plain browser, B would need an extra row inside the page, because a browser page has no titlebar to put tabs in.

5Option C: colour squares + host nameplate (review direction)

This is the direction from the 261124 review. It keeps a titlebar row but doesn't turn it into browser tabs. Each connected host is a coloured square, and clicking a square switches to that host. To the right of the squares sits a nameplate for the active host: its name, user@machine, OS and kind, connection type, and agent count. Selecting a square doesn't flood the band with a flat tint. The band lights up starting from that square, and the light slides over when you switch. Colour gives the quick "which one", and the nameplate confirms it in words. Hover a square to preview its host in the nameplate (dimmed, with →) without switching.

Why it doesn't read as a browser

There are no tab shapes and no per-host titles, and nothing joins the bar below the way an active tab does. The strip is a single identity panel: a palette next to a nameplate. Seven hosts take about 150px, not seven tab widths, and no host is ever squeezed into a monogram tab.

Making colour hold up

The nameplate always names the active host. Squares use well-separated hues. Today's accents don't work here: §2 shows ws-01, mac-mini and loom-box blurring together. The colour picker below only offers well-separated hues and labels any hue that another connected host already uses. A background host that's waiting gets an amber corner dot.

Key hints: the ⌥⌘ pill, with no layout shift

A small ⌥⌘ pill (Alt on Windows and Linux) sits to the left of the squares. Its space is always reserved, and it only becomes visible when you hover the title bar, so nothing moves when it appears. Holding ⌥⌘ (or hovering the pill) shows each square's number. The squares are a fixed 18px, big enough for a digit, so numbers appear inside them without anything resizing. The active square is marked by a ring, not a bigger size. Try it above: hover the strip, then hold ⌥⌘ (Alt on Windows/Linux) and press 1–4 to switch. The pill's tooltip also mentions ⇧⌘H, which moves focus to the squares.

Reordering: drag a square

Drag a square left or right. The others move aside, and while you drag every square shows its number, which updates live, so you can see the shortcut you're assigning. Dropping saves the order (the shell's existing reorderShellHosts(id, toIndex), one call per drop). The same order drives ⌥⌘1–9 and the native Hosts menu. Clicking without moving still switches hosts. With the keyboard, focus a square (⇧⌘H) and press ⌥← / ⌥→. The squares don't drag the window, so moving them is never mistaken for moving the window.

Why these settings are "This app", not "This device"

In the desktop app each host is a separate origin, so browser localStorage is separate per host. An effect chosen while viewing ws-01 would be gone when you switch to mac-mini. The two new settings go in the shell's own store (next to the host list, its order and the host colours), read and written over the bridge (e.g. prefs:get/prefs:set). Every host view gets a change event, so the strip updates on all hosts at once. A plain browser has no strip, so these rows are hidden there.

Where the data comes from: the name is the shell's display name. user@machine is the sshUser@hostname already worked out for deeplinks, and the OS, kind and link are derived. Background hosts' details come from their still-running views. Each host's SPA would report them to the shell the same way it reports its accent over accent:set, which means adding fields to the servers:list projection. The light effect is pure CSS: the gradients read three @property-registered variables (square position, nameplate end, colour), so switching just transitions those variables.

Settings → Appearance (live: drives the mock above)

Both new settings go in Appearance, under a third scope group, This app, between This host and This device. The strip effect is chosen from preview cards drawn with the real effect, not from a text list. Host colour replaces the instance-accent row. It's still a This-host setting, because a host's colour is part of its identity and every device should see the same colour. Rows marked with a green edge are new or changed. Click a card, an On-switch chip or a swatch, and the mock above updates.

6The macOS left edge: traffic lights + host + + Tab + toggle

This is the main risk with A. On macOS, the traffic lights take about 66px of the sidebar head. The two rows below show the head alone at the same width, once with the host in the head (replacing the wordmark) and once with the host as the first crumb (the head keeps just the logo). Drag the slider down to the narrowest sidebar width you actually use.

With the host as the first crumb, the head fits at every width with the logo, + Tab and the toggle. With the host in the head, the name gets squeezed: it falls back to a monogram on narrow sidebars. Putting it in the crumb also completes the breadcrumb: ws-01 › hexokit › …, with the tab as the centred heading.

7Browser and phone

In a browser there's no titlebar, so A's bar is just today's bar with a host crumb in it. To try it, set Platform → Browser in §3. One thing is still undecided: where a browser gets its list of hosts. The shell keeps that list in its own store, but a browser tab has nothing to read. Switching hosts in a browser also means going to another origin, not the shell's instant view swap.

Phone (375px)

A phone has no room for a host crumb in the bar. Below sm every crumb is already hidden. So the host moves into the drawer: the drawer's brand row, which shows the wordmark today, becomes the host switcher. A background host that's waiting puts an amber dot on the hamburger, so you can see it with the drawer closed.

9Recommendation

Updated after the review: Option C. Keep a titlebar row and make it the host switcher: one coloured square per connected host plus a nameplate for the active one. The band lights up from the selected square instead of a flat tint. Colour stays (you asked to keep it) but never has to work alone, because the nameplate always says the name. Option A is still the alternative if reclaiming vertical space ever matters more than colour. B is out: it looks like a browser.
