The operator wakes on idle.

No regular tick. A free Go check runs whenever an agent stops, and the operator — an AI run with a full toolset — is started only when the next step needs judgment. The autopilot keeps the queue; everything about PRs goes back to the operator.

What runs after R1–R6c. The loop became three layers: the clock, a Go check, and a Go rule table that acts on PRs before a model is consulted.

What six days of live data showed

Four servers, 2026-11-14 → 11-20: 2,110 loop fires, 168 model runs, 66 failed runs. The quiet-tick problem is solved — 87% of fires are a free no change, and idle servers settle at the 24-minute rung. The waste moved one layer down.

Two more findings sit underneath: every tracked pane has scope.stage: null because the check only ever diffs a stage baseline and never seeds one, so the stall detector reported "stage (unknown) over 30m" on agents that were running normally; and 74 of 118 run notes are no-op observations, which have already pushed three of your own notes below the brief's newest-ten window on loom.

Cost: 163 real runs at ≈ 203K input tokens each (38K written to cache, 164K read back), ≈ 33M tokens in total against the old operator's ≈ 840M. The goal is met by a wide margin even though each run is three to four times fatter than the 10–15K brief it was planned around — most of the extra is the run re-reading the whole ledger with track list --json.

The rule

Never wake the operator on a clock. Wake it when an agent becomes idle — meaning its work has actually stopped — or asks a question, and only when the next step cannot be decided mechanically. Everything the Go side still does must be cheap, deterministic, and visible.

Idle is the word that needs defining. Today it is the parent pane's own state, and a fab-fff parent is idle for thirty seconds between every stage while the worker it dispatched runs in the next pane. The check already sees both panes in one snapshot.

ObservedMeansWakes the operator?
waiting — a prompt is openthe agent asked somethingYes, at once. Routine prompts are answered; strategic ones get the defensible pick or you.
idle, and another pane in the same window or worktree is activewaiting on a worker it dispatchedNo. Not an edge; the baseline advances silently.
idle, nothing else active, held past a short floor (2–5 min)the agent is done or stuckYes. This is the wake the rule is about.
idle held 30 min after that wakethe run's answer did not move itOnce more per stretch (the existing aged condition).
pane gone · agent exited · PR / probe field changeda fact changed with no agent edgeOnly through the free check, which keeps polling on its own ladder — no agent involved.

On the data above, this definition removes roughly nine of every ten model runs and nearly all no-op notes, and changes nothing about when a prompt is answered.

Triggers

A trigger decides when to look; the check decides what changed. Because the check is edge-triggered and idempotent, a duplicate or spurious trigger costs one free Go check and a missed one is caught by the clock. That contract is what makes a new trigger source cheap to add and safe to get slightly wrong — none of them touches the run logic.

Every trigger enters through one door: rk operator wake -L <server> --reason <why>. The verb needs no daemon port — it writes a one-line marker under cron/<slug>.wake, the next 30 s tick consumes it and fires the loop with that reason, and the row lands in Activity. A hook can fire while the daemon is restarting without losing the trigger (Constitution II).

Surfaces: everything the operator does is visible

Today a wake and a scheduled fire both render in the Cron Log as operator loop · no change; the columns are entry, outcome, when. On loom that is 738 of the tab's 848 rows — the operator's real activity is drowned in its own heartbeat, in a table built for a different purpose. What the check probed, which pane woke it, what the mechanical pass did, and what the run was told live only in files under $XDG_STATE_HOME/hexokit/; the drawer shows a run's log path, copyable, never its contents.

The drawer keeps four segments. Each answers one question — talk to it · what is it tracking · what has it done · what else is scheduled — and the only button that starts anything is Check now.

Check now, and the trap

There is no manual fire today (rk cron tick only fires due entries). The obvious implementation — call rk operator check — is wrong: the check consumes the edges it reports, so a bare check run outside the loop swallows a change and the next loop fire reads "no change". The button goes through the loop runner: POST /api/operator/wake → a fire with reason manual → check → run if changed → one log line like any other fire; the busy gate applies ("run in progress, will check after"). The same verb on the CLI, rk operator wake -L <server>, and the same path the note composer uses. No separate "force a run": with notes as edges, Check now covers every case where you want the operator to look, and a forced run with nothing changed is exactly the paid no-op this removes.

Change list, smallest first

  1. Idle, defined. In operator.Check: an idle pane with an active sibling in its window or worktree is not idle; a bare idle must hold past a floor before it is a condition. Prompts stay immediate. (The cost win.)
  2. Seed the stage baseline in trackStage so stage_advance / review_fail fire and nothing reads "stage (unknown)" again.
  3. Failures climb, not reset. Consecutive run-failed lines move the ladder up like no change; one notification per streak, not per run.
  4. Re-scope the engine. Delete rows P4–P7, B1–B2, C1–C6, F1 and their executors (or demote restack / rebase to verbs); keep X/Q rows, the pass lock and the engine file. Drop Q6a.
  5. Give the operator its tools back. The brief's rules and allowlist regain git, gh and wt within the tiers; the merge section returns as prose for the three modes.
  6. Brief diet. The run stops dumping the whole ledger; a run that did nothing writes no note (or an observation the brief's ten-note window skips), so your notes never fall off.
  7. The trigger door. rk operator wake --reason writes the marker the tick consumes; the loop fire carries the reason; the check result is persisted on every fire; a user/chat note newer than the item's last run note is a condition. Check now and the PR receiver both call it.
  8. PR trigger. gh webhook forward in a sibling session plus the local receiver that maps PR events to the door; opt-in per repo, clock as fallback.
  9. Surfaces. The drawer becomes Terminal · Tasks (with the Needs-you band) · Activity (reason, check summary, run with brief and log inline, Check now) · Cron (list and log merged, loop rows behind a toggle); the mobile operator route mirrors the strip through ?tab=.
  10. Housekeeping. Remove the muted legacy operator tick entries on all four servers.

Decisions and open questions

Regular tickGone for the agent; the Go poll staysThe poll is what notices a PR or probe change with no agent edge, and it costs nothing.
Idle floorWindow-aware first; a 2–5 min floor as the fallbackThe window rule is derivable from one snapshot (Constitution X); the floor covers an agent with no worker pane.
PR workOperator, with the engine's executors available as verbsJudgment where the outcome space is wide; a deterministic helper where the operator wants one.
