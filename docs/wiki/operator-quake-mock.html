Click the drawer's tabs to switch between Runs, Chat, Tasks and Cron. On a phone, scroll the frame sideways.

  1. Four tabs: Chat, Tasks, Runs, Cron. Today the drawer has Operator Terminal, Operator Tasks, Cron List and Cron Log. The terminal becomes Chat, the two cron tabs merge, and Runs is new.
  2. Runs is where scheduled checks report. Each check is one row. Checks that found nothing collapse into a single "no change ×31" row and cost $0. Expanding a row shows what changed, which directive applied and what the run did.
  3. The header counts checks, runs and today's spend. "Chat idle 41m" is the chat session, which no longer gets interrupted by ticks. "Checked 2m ago" is the scheduler.
  4. Anything that needs you arrives as a push notification and a tab note, not as text typed into your chat.
  5. The pinned operator row is still the home chat. Other tabs can join as operator chats (see below), but the drawer and ⌘J always open this one.

Any tab can become an operator chat

Because checks no longer run inside a chat, a chat is just the operator skill plus the shared state file. Typing /fab-operator in any agent tab joins it. It sees the same tracked items and directives and can act on them. It never receives scheduled checks, and it does not take over the pinned role.

Answers to the open questions

Can any tab become an operator chat with /fab-operator?

Yes. Without ticks, a chat is just the skill plus the state file, so any number of tabs can join. Keep one pinned home (the role=operator window) for ⌘J, the sidebar and notifications. Concurrent writes go through a lock on the state file.

Do scheduled runs get their own terminal?

No terminal. A run writes its transcript and a one-line outcome to the operator's run log, and HexoKit shows them in the Runs tab. Typing results into the chat would cost a full chat turn each time, which is what we're removing.

This needs a run-kit change: rk cron only types prompts into panes today, so it would need to be able to run a command (fab operator tick) on its schedule.

How many tabs in the drawer?

Today four: Operator Terminal, Operator Tasks, Cron List, Cron Log. Proposed four: Chat, Tasks, Runs (new), Cron (list and log merged).

Which prompt cache?

Plan for a cold cache. In 390 recent transcripts, most interactive sessions used the 1-hour cache, but every dispatched worker run (the closest thing to a scheduled check) used the 5-minute cache, and checks with changes are often more than 5 minutes apart. So keep the check's prompt small (a short tick prompt, only the tools it needs) so a cold start costs cents. A warm cache is a bonus. This also works for codex and kimi, which manage caching their own way.

Which actions need Opus?

Split by how reversible the action is. Sonnet handles looking, bookkeeping, notifying you and answering routine prompts covered by a rule. A run escalates to Opus before it answers a non-routine question from an agent, spawns an agent, or sends anything not covered by a rule. Merging, closing PRs and deleting branches always go to you. In snappy-gopher only 21 of 1,563 ticks sent anything to an agent, so escalations are rare and cheap.
